# 「阅观年度」小程序优化方案

> 基于 3 份调研（成就系统 / 报告生成系统 / 代码现状盘点）综合产出。
> 所有建议针对当前约束：**个人主体、纯本地存储、无 AI、无社交、无支付**，并遵守 `es6:false`（无 `?.` / `??`）。

---

## 一、诊断：当前小程序的核心问题（按严重度排序）

### 🔴 P0 严重问题（影响产品核心价值）

#### 1. 统计能力严重浪费——「算了不用」
**现状**：`stats.ts` 实现了 9 个统计函数（calcOverview / calcGenreStats / calcMonthlyStats / calcRatingDist / calcTypeRatio / calcFootprint / calcQuotes / calcTopItems / calcAnnualKeywords），但主界面几乎没消费：
- 首页只用了：年度关键词（1 个词）+ 目标进度 + 勋章墙
- 列表页只用了：3 条文字彩蛋
- **未展示**：总成就数、书影数、平均分、最长连续天数、体裁分布、月度分布、评分分布、类型占比、阅读足迹、金句墙、高分榜

**对比**：GitHub 用 365 格热力图把全年 commit 压成一张图；Goodreads 用柱状图把月度读书铺满；微信读书把阅读时长做成超大数字。这些都是「计算已经做了」的现成能力，只是缺一个**统计页**来承载。

**影响**：用户录入越多数据，越想知道「我的数据告诉我什么」，但当前小程序把最有价值的洞察藏在代码里。

#### 2. 首页信息架构过载——9 个区块堆叠
**现状**：首页顺序 = hero → 年度目标进度卡 → 勋章墙卡 → 成就墙 → actions → 报告入口 → 最近成就 → 双入口 → 底部链接。
- **新用户（无数据）**：体验尚可（很多条件渲染隐藏）
- **中度用户（设了目标 + 有勋章 + 有愿望 + 有灵感 + 有报告）**：首屏极长，核心 CTA「录入」被推到很下面
- **冗余**：年度目标进度条和勋章墙进度条在视觉上几乎重复（都是 current/target 横条），并存时削弱每一项的份量

**对比**：Duolingo / 微信读书 / Keep 都是「顶部紧凑数据胶囊条 + 下方主体」双层结构，把核心指标压缩进一行。

#### 3. 纯本地存储无导出/备份——成就系统的伦理底线
**现状**：所有数据纯本地，卸载即全丢；隐私政策提了，但**没提供任何导出/导入手段**。
**对比**：成就系统的核心价值是「积累」，丢数据等于毁掉所有累积。调研明确指出这是伦理底线。
**影响**：用户长期使用后会因不敢换机而放弃，或在换机时归零——比没有成就系统更糟。

### 🟠 P1 重要问题（影响体验和留存）

#### 4. 缺失核心功能（同类应用直觉上应该有的）

| 缺失功能 | 同类参照 | 影响 |
|---|---|---|
| **搜索** | 几乎所有记录类应用 | 数据多了找不到（按标题/作者/标签/短评） |
| **排序选项** | Goodreads / Letterboxd | 列表只能按日期降序，无法按评分/分类排 |
| **成就详情页** | Letterboxd / 豆瓣 | 点成就只能进 edit，无只读详情（完整金句/理解长文/图片大图）|
| **时间线/日历视图** | GitHub 热力图 / Apple Health | 无「按月日历」或时间线，丢失「走过一年」的仪式感 |
| **标签筛选/云** | StoryGraph mood 标签 | 情绪/五感标签打了但无任何聚合/筛选 |
| **数据统计页** | Spotify Wrapped / 微信读书 | 9 个统计函数全定义但无专门页面消费 |
| **连续打卡（streak）** | Duolingo / Forest / 微信读书 | 调研结论：跨品类最高共识的设计，缺失损失巨大 |
| **三态管理** | Goodreads / 豆瓣「想读/在读/读过」 | 当前只有「愿望→成就」二态，无「在读中」中间态 |
| **成就图片墙** | Letterboxd 海报墙 / 微信读书书封墙 | 8 种预设图 + 用户上传图散落在各 edit 页，无总览 |

#### 5. 导航/层级混乱

| 问题 | 详情 |
|---|---|
| **模板管理无主导航入口** | templates 页只能从 report 组装器（选模板）间接进入，独立管理入口缺失 |
| **设置页单一长滚动** | 主题 + 暗色 + 字体 + 年度目标 + 关键词 + 勋章全平铺，无分组；目标和勋章编辑混在外观设置里，语义跳跃 |
| **愿望转化路径隐藏** | 愿望→成就的唯一入口是 list 页底部灰显区或许愿星页的「完成」按钮，链路长 |
| **灵感纯孤岛** | 记录后只能本页查看/编辑/删除，不能转成愿望、不能转成成就、不能进报告——长期价值低 |
| **报告无「再生成」快捷入口** | report-edit 只能编辑当前报告，想换模板要重走全部三步 |

#### 6. 视觉一致性问题

| 问题 | 详情 |
|---|---|
| **报告样式系统与应用主题割裂** | app 主题（CSS 变量）vs 报告 CardStyle（独立 bgType/bgColor/bgGradient）两套系统无关联；暗色主题下编辑亮色卡片，割裂感强 |
| **成就卡片视觉三套不一致** | 首页 wall-card / list 页 item-card / report 选书 book-row 三套样式，badge 形态、信息层级、配色都不统一 |
| **空状态 emoji 风格不统一** | 🏆 / 🌱 / ✦ / 📋 / 📭 混用，无统一品牌图形 |
| **添加入口形态全不一致** | 首页用 actions 区块、list 用 FAB、wishlist/inspiration 用顶部添加行、reports 用空状态按钮 |

### 🟡 P2 锦上添花（提升质感但不紧急）

- 勋章系统单薄（只有 4 枚，其它 5 个分类无勋章，milestone/yearly/streak 全预留）
- 无稀有度分级、无解锁动画/振动、无空状态 CTA

## 二、优化方案（按优先级分层）

### 🚀 第一优先级：立刻能做、ROI 最高

#### 方案 A：新建「数据回顾」页（消化所有被浪费的统计）

**这是当前最大的优化杠杆**。9 个统计函数已经写好，只差一个页面来展示。

**页面结构**（新页面 `pages/stats/stats`，从首页入口进入）：

```
顶部：年度切换条（复用 list 页的年份切换）
├── 总览仪表盘（calcOverview）
│   ├── 大数字：总成就数 / 书数 / 影数（横向 3 列）
│   ├── 平均分（星级 + 数字）
│   └── 最长连续天数 + 独立记录天数
├── 月度分布柱状图（calcMonthlyStats）
│   └── 12 月柱状，高亮峰值月（GitHub 风）
├── 评分分布（calcRatingDist）
│   └── 0.5-5 星横向柱状（星级 + 条形）
├── 体裁 Top 分布（calcGenreStats）
│   └── 横向条形图，top 6 体裁
├── 分类占比（calcTypeRatio + countByCategory）
│   └── 书/影 环形图 + 各分类占比
├── 阅读足迹（calcFootprint）
│   └── 按地点聚合的列表（"你在咖啡馆读了 3 本"）
├── 金句墙（calcQuotes）
│   └── 所有金句的瀑布流卡片
└── 高分榜（calcTopItems）
    └── 评分 ≥4.5 的成就排行榜
```

**工作量**：1 个新页面（wxml/ts/less/json），复用现有所有 stats 函数，纯展示无新逻辑。约 400-500 行。

**预期收益**：
- 用户「数据越多越想看」的闭环成立
- 报告生成时有现成可视化参考
- 直接对标 Spotify Wrapped / 微信读书年度报告的「数据可视化」核心

#### 方案 B：首页信息架构瘦身

**目标**：把 9 个区块压缩到 5 个，核心 CTA 上浮。

**新结构**：

```
1. 紧凑 hero（年份 + 年度关键词 + 一行数据胶囊条）
   └── 胶囊条：[🔥 streak天数] [📚 N本] [🎬 N部] [🎯 目标%]
2. 成就墙（核心展示，列数切换 + 查看更多）
3. 主行动区（继续记录 + 生成报告 + 数据回顾 三按钮）
4. 双入口卡（许愿星 + 灵感抽屉）
5. 底部链接（设置 / 关于 / 数据回顾）
```

**改动**：
- 把年度目标进度卡 + 勋章墙卡合并成 hero 区的「数据胶囊条」（紧凑数字而非独立卡片）
- 详细进度（目标 / 勋章）移到新的「数据回顾」页或设置页
- 「我的报告」入口从独立卡降级到 actions 行的一个按钮（减少一个区块）

**预期收益**：
- 首屏 CTA 上浮 2-3 屏
- 核心数据一眼可见（胶囊条），详细数据进「数据回顾」
- 视觉冗余消除（不再有目标条和勋章条并存）

#### 方案 C：数据导出/导入（伦理底线）

**新模块** `utils/backup.ts` + 设置页入口：

```typescript
// 导出：把所有 storage key 合并成一个 JSON，存到本地文件
export function exportAllData(): string {
  const data = {
    version: CURRENT_SCHEMA_VERSION,
    exportedAt: Date.now(),
    book_film_data: wx.getStorageSync('book_film_data'),
    report_instances: wx.getStorageSync('report_instances'),
    report_templates: wx.getStorageSync('report_templates'),
    wishlist: wx.getStorageSync('wishlist'),
    inspirations: wx.getStorageSync('inspirations'),
    app_preferences: wx.getStorageSync('app_preferences'),
  }
  return JSON.stringify(data, null, 2)
}

// 导入：校验版本 + 合并/覆盖
export function importAllData(json: string): { ok: boolean; msg: string } { ... }
```

**交互**：
- 设置页加「备份与恢复」区
- 导出：用 `wx.getFileSystemManager().writeFileSync` 写到用户目录，提示文件路径（或用剪贴板复制 JSON）
- 导入：从剪贴板粘贴 JSON，或选文件读取
- 进阶：导出前显示数据条数（"将备份 47 条成就、3 份报告、12 条愿望"）

**预期收益**：解决换机丢数据的根本焦虑，让用户敢长期投入。

### 🎯 第二优先级：补齐核心缺失功能

#### 方案 D：连续打卡（streak）机制

**调研结论**：跨品类最高共识的设计（Duolingo / Forest / 微信读书 / GitHub 全有）。缺失损失巨大。

**数据层改动**（`storage.ts`）：
```typescript
// 不需要新增字段——streak 从 finishedDate 现算
// 新增 stats.ts 函数：
export function calcStreak(items: Item[], category?: string): {
  current: number      // 当前连续天数（今天/昨天有记录才算）
  best: number         // 历史最长连续
  lastDate: string     // 最近一次记录日期
}
```

**UI**：
- 首页胶囊条加一个「🔥 streak」数字（最长连续记录天数）
- 数据回顾页加「连续记录」卡：当前 streak + 历史最佳 + 火苗图标
- **不做强提醒**（纯本地小程序没推送能力，也没必要做 Duolingo 式焦虑推送）

**宽容机制**（调研强调「没有宽容的 streak 会逼走用户」）：
- 当前阶段不强制天天记录（读书观影本来就不是每日行为）
- streak 定义为「连续 N 天有记录」，允许中间隔 1-2 天（参考 Streaks 的弹性目标）
- 或者干脆定义为「本月有记录的天数」+「历史最长月」——更符合读书观影的真实节奏

#### 方案 E：成就详情页

**现状**：点成就只能进 edit 编辑页，无只读详情。
**改动**：新建 `pages/detail/detail` 页面，承载完整信息展示：

```
├── 顶部大图（图片预设/上传图大图展示）
├── 标题 + 作者 + 类型 + 评分
├── 完成日期 + 分类标签
├── 短评
├── 阅读情境（地点 / 心境 / 我的理解 —— 长 text）
├── 金句墙（所有 quotes 卡片瀑布流）
├── 情绪与五感标签（chip 云）
├── 关联愿望（如果有 wishId，显示来源）
└── 底部：编辑 / 删除 / 分享单条成就海报
```

**改动要点**：
- edit 页保留「编辑」职责，detail 页承担「展示」职责
- 列表页点成就 → 先进 detail → detail 有「编辑」按钮跳 edit
- detail 可以加「分享单条成就海报」（canvas 合成一张竖版卡片）——补齐「无分享单条成就」的缺失

### 🎨 第三优先级：视觉与体验打磨

**现状**：首页 wall-card / list 页 item-card / report book-row 三套样式。
**改动**：抽出一个 `<achievement-card>` 自定义组件，参数化（compact/normal/detail 三档密度），全项目复用。
- 统一 badge 形态（圆形分类图标 + 分类色）
- 统一信息层级（图标 → 标题 → 副信息 → 评分 → 标签）

#### 方案 I：勋章系统增强

**当前**：4 枚（reading50/100, film24/50），无解锁动画，无空状态 CTA。
**增强方向**（对照调研）：

1. **扩充勋章数**：每个预设分类都配 2 档（入门/进阶）→ 7 分类 × 2 = 14 枚
2. **稀有度三档**：普通（灰/铜）/ 进阶（银）/ 稀有（金 + 右上角钻石角标，参考 Xbox）
3. **进度型 vs 纪念型分层**：
   - 进度型（带进度条）：累计读 N 本、累计观 N 部、写 N 条笔记
   - 纪念型（瞬间解锁，无进度条）：读完第 1 本、首条金句、首次五星、首次连续 7 天
4. **解锁反馈**：徽章缩放弹出 + 振动（`wx.vibrateShort`）+ 飘字「+1 成就」
5. **空状态**：未读任何书时显示「读完第 1 本，解锁【初心读者】徽章」+ CTA
6. **叙事化命名**（任天堂哲学）：「夜读达人」而非「连续 7 天夜间阅读」；「书海启航」而非「累计 10 本」

#### 方案 J：年度回顾报告模板增强

**现状**：已有 8 套内置模板，但报告是「用户选书写」，不是「年度回顾」。
**对照调研**：Spotify Wrapped / 微信读书年度 / 豆瓣年度 都是「全年数据自动生成」的 Wrapped 式报告。

**新增模板类型**：「年度回顾」模板——基于全年成就自动填充（不是选书）：

```typescript
// template-engine.ts 新增变量：
extractAnnualVars(allItems: Item[], year: number): {
  totalCount, bookCount, filmCount,
  avgRating, topCategory, topMonth,
  longestStreak, bestBook, bestFilm,
  favoriteGenre, readingPlaces, totalQuotes,
  annualKeyword, annualPersona,  // 年度气质标签
  ...
}
```

**内置「年度回顾」模板**（参考调研的 8 个标配章节）：
1. 开场封面（年度主题句 + 年份）
2. 总数字（"今年你记录了 N 个成就"）
3. Top 成就封面墙
4. 分类占比（标签云 / 环形）
5. 月度分布柱状 + 数据彩蛋（"你最常在 X 月记录"）
6. 高光里程碑（最长连续 / 最高分 / 最厚的一本）
7. **年度人格卡**（翻牌揭晓，16 型阅读者）
8. 金句精选（用户自己写的金句）
9. Summary 海报

**工作量**：较大，但能在现有报告系统上扩展（template-engine + poster 已经支持变量替换和 canvas 绘制）。

#### 方案 K：年度人格卡（文学化差异化武器）

**调研结论**：Spotify 的 Me in 2023 / 网易云的年度关键词 / 微信读书的年度阅读角色——人格化卡片永远是 Wrapped 的情绪高潮。

**设计**：16 型读书者 + 12 型观影者，基于 4 维度组合：
- 时段：晨读者 / 夜读者
- 深度：精读派 / 速读派
- 偏好：文艺 / 通俗 / 杂食
- 节奏：稳健 / 爆发

**实现**：纯前端规则引擎（决策树），从 stats 数据推导，每型配一个插画 + 一段文案。

#### 方案 L：报告文学化文案引擎

**现状**：报告文案是用户手写或模板静态。
**增强**：基于数据动态生成金句（调研的「把数字翻译成情境」）：

```typescript
// utils/copywriting.ts
export function generateInsightCopy(stats: OverviewStats, profile: PersonaResult): string[] {
  const copies: string[] = []
  // 物理类比
  if (stats.bookCount > 0) {
    copies.push(`这 ${stats.bookCount} 本书摞起来，约 ${(stats.bookCount * 0.025).toFixed(1)} 米`)
  }
  // 时段洞察
  if (stats.peakHour >= 22 || stats.peakHour < 5) {
    copies.push(`凌晨 ${stats.peakHour} 点的你，比白天更诚实`)
  }
  // 百分位（基于本地数据分布，非全网）
  copies.push(`你的平均分 ${stats.avgRatingText}，是个温柔的评分者`)
  return copies
}
```

**注意**：调研强调「避免 AI 味」——不要堆砌「愿你新的一年」「感谢一路有你」，用意象名词收尾（豆瓣「月光穿过盐粒」风）。

### 🔧 第四优先级：长期重构

#### 方案 M：三态管理（想读/在读/读过）

**对照**：Goodreads / 豆瓣 / 微信读书 / Letterboxd 全部采用。
**现状**：只有「愿望（想读）→ 成就（读过）」二态，无「在读中」。
**改动**：
- Item 加 `status?: 'reading' | 'done'` 字段（默认 done 兼容老数据）
- 愿望转化时可选「开始读」→ 生成 status=reading 的 Item（不计入勋章计数，但显示在「在读」区）
- 首页或列表页加「在读中」区

**权衡**：改动较大（涉及勋章计数口径、报告变量），建议放后期。

## 五、调研引用的关键洞察（对照当前小程序）

### 来自成就系统调研
1. **「数据胶囊条 + 主体」双层结构**（Duolingo/微信读书/Keep）→ 当前首页是 9 区块堆叠，应瘦身
2. **未解锁徽章必须「灰而可读」**（Steam/Xbox）→ 当前勋章墙已做到（进度条 + ✓）
3. **进度条分子/分母双写**（所有产品）→ 当前已做到（current/target）
4. **streak 是跨品类最高共识**（Duolingo/Forest/微信读书/GitHub）→ 当前缺失
5. **年度回顾是最高 ROI**（Goodreads/Strava/豆瓣）→ 当前报告是「选书写」，不是「全年自动生成」
6. **稀有度三档 + 钻石角标**（Xbox）→ 当前勋章无稀有度
7. **段位头衔**（Todoist Karma）→ 当前无（可加：书虫→书癖→藏书家）
8. **叙事化命名**（任天堂）→ 当前勋章名是「阅读 50 本」，可改成「书海启航」
9. **解锁反馈三件套**（弹层 + 振动 + 飘字）→ 当前勋章解锁无任何反馈

### 来自报告生成系统调研
1. **全屏纵向滑动 H5 卡片**（豆瓣/网易云/微信读书）→ 当前报告是 swiper 卡片，接近但可优化
2. **8-10 张卡最佳长度**（Spotify Wrapped）→ 当前模板 6-8 卡，合理
3. **人格化卡片是情绪高潮**（Spotify Me in 2023）→ 当前只有年度关键词，无人格卡
4. **最后一张永远是 Summary 海报**（Spotify）→ 当前有导出海报，但不是「年度主题句 + 3 数字 + 人格」的精炼版
5. **封面墙瀑布流**（阅读/观影类标配）→ 当前报告未用封面墙
6. **24h 时段热力条 + 数据彩蛋**（网易云/微信读书）→ 当前无（需录入时段数据，或从 finishedDate 近似）
7. **标签云是文学化最佳载体**（豆瓣/StoryGraph）→ 当前情绪/五感标签打了但无云
8. **年度主题句**（豆瓣「月光穿过盐粒」）→ 当前有年度关键词但不是意象化
9. **把数字翻译成情境**（"摞起来 1.4 米"）→ 当前无
10. **极简意象收尾，避免 AI 味**（豆瓣/Letterboxd）→ 当前模板文案偏中性

### 来自代码盘点
1. **stats.ts 9 个函数几乎没在 UI 用** → 最大浪费
2. **首页 9 区块过载** → 需瘦身
3. **成就卡片三套样式不一致** → 需统一
4. **添加入口形态全不一致** → 需统一
5. **灵感纯孤岛无出口** → 需加转化路径
6. **报告样式与 app 主题割裂** → 编辑器体验问题
7. **无搜索、无排序、无详情页** → 核心功能缺失

## 六、不做清单（明确边界）

基于调研和合规约束，以下**不做**：

- ❌ 朋友排行榜 / 联赛（无社交）
- ❌ 全网稀有度百分比（无服务端）
- ❌ AI 推荐 / AI 总结文案（无 AI）

- ❌ 重度 RPG 游戏化（Notion 启示：劝退）
- ❌ 真人头像 / 明星资源（无版权）
