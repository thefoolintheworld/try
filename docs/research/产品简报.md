## 0. 项目定位（一句话）

用户在微信小程序里录入自己今年读过的书、看过的电影，一键生成一张**豆瓣暖色风格的精美年度报告海报**，保存到相册发朋友圈。附带本地书架/影单记录页和统计可视化，可作为长期使用的个人书影音管理工具。

## 1. 为什么做这个（基于真实需求，不是凭空想象）

| 维度 | 证据 |
|---|---|
| **需求真实** | 豆瓣每年"我的书影音年度总结"刷屏，证明"晒自己读了什么看了什么"是真实且强传播的需求 |
| **个人主体合规** | 纯工具，无 UGC、无社交信息流、无 AI 生成、无交易——落在"工具-信息查询"类目，是前面调研验证过的个人主体最安全区 |
| **可传播** | 调研硬证据：年度报告类小程序（地图年度、收款年度）已多次验证"晒朋友圈+二维码回流"的病毒传播闭环 |
| **能力证明** | 本项目的真实目标不是"做某个产品"，而是"证明能独立做出一个能跑、能上线、有陌生人用的小程序"——这个产品完整覆盖小程序开发全链路（数据存储、canvas 绘图、用户交互、合规上线） |
| **vibecoding 友好** | 数据驱动（列表 CRUD）+ canvas 海报渲染 + 简单统计，AI 最稳的类型；几乎不需要复杂的平台 API |

---

## 2. 合规边界（必须严守，否则审核被拒）

依据：前面 `市场需求调研.md` 的硬证据。

✅ **可以做的**：
- 用户自己录入自己的书/影数据（本地存储）
- 生成海报让用户自己保存到相册（用户主动分享，非平台 UGC）
- 统计用户自己的数据（评分分布、类型占比）

❌ **绝对不能做的**（任何一条都会被审核拒）：
- 用户之间互看对方的书单/影评（社交信息流）
- 提供书/影资源播放或下载
- 用 AI 大模型生成影评/推荐（触发"深度合成"类目，个人主体被禁）
- 抓取豆瓣等内容平台的数据展示
- 任何形式的电商/付费

**关键纪律**：所有数据都是"用户自己的 + 存在本地的"。这是合规的基石。

---

## 3. 产品功能（三块）

### 3.1 核心生成器（MVP 必做）
- 录入书/影条目（最少：标题、类型、评分、看完日期、可选短评）
- 年度报告生成：汇总成一张海报，含核心数字 + 统计可视化 + 暖色设计
- 海报保存到相册

### 3.2 本地记录页（让产品可长期使用，不只是用一次）
- "我的书架/影单"列表，按时间/评分筛选
- 条目的增删改查（纯本地）

### 3.3 统计可视化（让海报有"作品感"和"工程感"）
- 评分分布（柱状/雷达）
- 类型占比（环形图）
- 月度趋势（折线）
- 核心数字（今年 X 本 / Y 部 / 平均分 Z / 最爱类型）

## 4. 数据模型（先定这个，再让 AI 写代码）

```typescript
// 单个条目（书或影）
type Item = {
  id: string           // uuid
  type: 'book' | 'film'
  title: string
  author?: string      // 书的作者 / 影的导演（可选）
  genre: string        // 类型标签，如 '小说' '科幻' '纪录片'
  rating: number       // 1-5（允许 0.5 步进，即 0.5/1/1.5/.../5）
  finishedDate: string // ISO 日期 'YYYY-MM-DD'
  note?: string        // 短评（可选）
  coverColor?: string  // 海报里条目卡片的代表色（可选，自动生成）
}

// 用户全年数据
type YearData = {
  year: number         // 2026
  items: Item[]
}
```

**存储**：全部用 `wx.setStorageSync`（本地存储），不上云开发、不要后端。
**理由**：① 合规（数据完全在用户手机，不涉及内容展示给他人）② 简单（vibecoding 友好）③ 成本零。

## 5. 页面结构（5 页）

```
1. 首页（dashboard）
   - 核心数字概览（今年 X 本 / Y 部 / 平均分）
   - 两个 Tab：书 / 影
   - 主 CTA：「生成我的年度报告」
   - 最近添加的几条

2. 列表页（书架/影单）
   - 全部条目列表，卡片式
   - 筛选：按时间/评分/类型
   - 右下角浮动 + 按钮添加

3. 添加/编辑页
   - 表单：标题、类型、评分（星级选择器）、日期、短评
   - 自动建议类型（常见类型快捷标签）

4. 年度报告页（核心）
   - 自动汇总当年数据
   - 多屏可滑动（数字概览 → 类型占比 → 评分分布 → 月度趋势 → 高光条目）
   - 底部「生成海报」CTA

5. 海报预览/保存页
   - canvas 绘制的最终海报
   - 「保存到相册」按钮
   - 保存成功后的引导（提示去朋友圈分享）
```

## 6. 设计规范（豆瓣暖色风）

### 配色
```
主背景：#FAF6F0（暖白米色）
卡片底：#FFFFFF
主文字：#3D3530（暖深棕，非纯黑）
次文字：#8B7D6E
强调色：#D97A4A（豆瓣橙，用于按钮/高亮）
辅助色：#6B8E5A（书的绿）、#8B6F9C（影的紫）
评分星：#E8A33D
分隔线：#E8E0D5
```

### 字体
- 标题：思源宋体（serif，有文学感）/ 小程序默认 serif fallback
- 正文：系统默认 sans-serif
- 数字（年报里大数字）：可用更大的字号 + serif，强调"年报感"

### 海报构图（核心，决定"一眼惊艳"）
- 顶部：年份大字 + "我的阅读观影年报" + 用户头像（可选）
- 中部：核心数字三联（X 本 / Y 部 / 平均分 Z）
- 中下部：类型占比环形图 + 评分分布小柱图
- 底部：高光条目（评分最高的 3 条，带封面色块和标题）
- 最底：小程序码（关键！这是回流闭环）+ 一句 slogan（如"看看你的这一年"）

### 动效
- 年报页滚动到统计部分时，数字从 0 滚动到目标值（年报感的关键）
- 海报生成时有个简短的处理动画

## 7. 技术要点与避坑（给 AI 编程助手）

### 7.1 canvas 海报绘制（最关键的技术点）
- 用小程序 canvas 2D API（`type="2d"`，不是老版 canvas）
- **关键坑**：canvas 2D 模式下，绘制前必须等 `canvas` 节点通过 `SelectorQuery` 取到，且要设置 `dpr`（高分屏否则模糊）
- 保存到相册：`wx.canvasToTempFilePath` → `wx.saveImageToPhotosAlbum`，**需要用户授权 scope.writePhotosAlbum**
- 海报尺寸建议：750 × 1334（小程序标准比例，适合竖屏分享）

### 7.2 数据存储
- 用 `wx.setStorageSync('yearData', data)` / `wx.getStorageSync`
- **不要**用云开发（增加复杂度和合规审查面）

### 7.3 星级评分组件
- 用半星选择器：5 星 × 2 = 10 档（0.5 步进）
- 可以自己用 view + WXSS 实现，不必引第三方组件

### 7.4 统计可视化
- **不要**用复杂的图表库（包大、AI 写不稳）
- 简单的柱状/环形/折线，用 canvas 或纯 view + WXSS（CSS）实现
- 环形图：用 CSS conic-gradient 或 canvas arc 都行

### 7.5 给 AI 护栏
1. 所有数据走本地存储，绝不假设有后端
2. canvas 绘制函数封装清晰（一个画海报的函数，参数是 YearData），便于 AI 单独迭代
3. 设计令牌（上面的配色）抽成常量文件，AI 引用而非硬编码
4. 类型（Item / YearData）锁死，UI 从类型读
5. 每次改完跑"微信开发者工具的编译"，看模拟器是否正常

## 8. 开发计划（里程碑）

每个里程碑"让 AI 写一段、编译看效果、再下一个"。

### M1 — 环境与空骨架（半天）
- 注册个人主体小程序拿 AppID（或先用测试号）
- 安装微信开发者工具
- 新建项目，跑通空页面，模拟器能开
- 完成首页 + 列表页的静态布局（用假数据）

### M2 — 数据层 + CRUD（1-2 天）
- 实现 Item / YearData 类型 + 本地存储读写
- 列表页接真数据
- 添加/编辑页表单完成
- 能增删改查条目

### M3 — 统计可视化（1-2 天）
- 实现统计计算（按类型聚合、评分分布、月度趋势）
- 在年报页用纯 CSS/canvas 画出环形/柱状/折线
- 数字滚动动画

### M4 — 海报生成（1-2 天，最关键）
- canvas 2D 绘制海报（按设计规范构图）
- 保存到相册流程（含授权处理）
- 海报预览页

### M5 — 打磨 + 上线（1-2 天）
- 体验细节（空状态、加载、错误处理）
- 提交审核（个人主体 + 工具类目）
- 等审核通过 → 生成小程序码 → 可分享

**总周期**：5-9 天（vibecoding 节奏）

## 10. 给后续实施的提示

- **本简报是开发依据**，AI 编程助手应据此 + `市场需求调研.md` 的合规边界来写代码
- **合规底线不可破**：见第 2 节
- **设计是关键卖点**：豆瓣暖色风 + 海报构图（第 6 节）必须做到位，否则作品感不足
- **canvas 海报是技术难点**：第 7.1 节的坑要特别注意，AI 第一次写很可能 dpr 没处理对导致模糊
- **数据模型锁死**：第 4 节的 Item / YearData，不要让 AI 自由发挥字段
