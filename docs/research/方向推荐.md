5 个推荐方向，按"展示性 × 可行性"综合排序：

**如果只想做一个、求稳出活**：选 **#3 个人主页/数字名片** —— 最简单、最像"作品"、分享路径最自然（小程序码发朋友圈）。
**如果想要"有点意思"的展示品**：选 **#2 电影/书单清单** —— 数据驱动、AI 写得稳、年度回顾卡片天然有传播性。

## 1. 生日/纪念日提醒器

**一句话**：记录亲友的生日和纪念日，主页是一个温暖的倒数时间线，临近时有提醒和卡片模板。

- **类目**：工具类 - 备忘录（个人可做 ✓）
- **核心功能**（4 个）：
  1. 添加纪念日（名称、日期、类型、备注、头像）
  2. 主页时间线：按"还有 X 天"排序，带柔和的进度环
  3. 详情页：历年回顾、一键生成祝福卡片图（canvas 绘制，可保存到相册）
  4. 提醒（订阅消息，需用户主动订阅）
- **页面数**：4 页（主页/添加/详情/设置），交互中等偏低
- **vibecoding 友好**：★★★★★
  - 数据驱动（一个 `anniversaries[]` 数组渲染时间线），AI 写列表渲染最稳
  - 唯一平台 API 是"订阅消息"和"保存图片到相册"，可控
  - 卡片生成用 canvas 2D API（`wx.canvas`），官方有标准文档可喂给 AI
- **展示亮点**：
  - 倒数进度环 + 暖色系配色，视觉温馨
  - "一键生成祝福卡片"是传播点（用户保存图发朋友圈，自然带上你的小程序）
- **参考**：Web 端有 "Days Matter"（倒数日）、各种 anniversary tracker；小程序里搜"倒数日"有大量同类，证明需求真实存在
- **周期**：3-5 天

## 2. 电影/书单"已看清单"（⭐ 推荐重点）

**一句话**：记录你看过的电影和书，打分 + 短评，年底自动生成"年度回顾卡片"。

- **类目**：工具类 - 信息查询（个人可做 ✓；纯个人记录，不涉及内容传播和版权销售）
- **核心功能**（5 个）：
  1. 搜索添加（接公开 API，如豆瓣开放接口或 OMDB；或纯手动输入）
  2. 打分（5 星）+ 短评 + 标签 + 看完日期
  3. 列表页：按时间/评分/类型筛选，卡片式展示
  4. 统计页：本年看了多少部、最爱的类型、评分分布（简单图表）
  5. **年度回顾卡片**：自动汇总生成一张可分享的图（这是传播点）
- **页面数**：5 页（首页/搜索/详情/统计/回顾），交互中等
- **vibecoding 友好**：★★★★★
  - 全程数据驱动（`items[]` 渲染卡片列表），AI 最擅长
  - 几乎不用平台 API：搜索接 HTTP（`wx.request`），卡片用 canvas
  - 没有实时、没有支付、没有复杂数据库（用本地存储 `wx.setStorageSync` 就够，连云开发都可以不上）
- **展示亮点**：
  - 年度回顾卡片是天然的"作品展示物"——做出来你自己用一年，年底发朋友圈就是一张漂亮的图，自带话题
  - 数据可视化（评分分布、类型占比）让作品显得"有工程感"
- **参考**：
  - Web：Letterboxd（letterboxd.com，电影社交，核心是"已看清单+评分"）
  - 豆瓣的"我的书影音"年度总结（每年刷屏的那张图就是这个套路）
  - 小程序：搜"我的电影清单""读书笔记"有同类
- **周期**：5-7 天
- **版权提醒**：纯记录自己看过的、自己打分写短评，属于个人使用；不要做"提供资源播放/下载"，也不要批量抓取豆瓣数据上线（那是另一回事）。

## 3. 个人主页/数字名片（⭐ 求稳首选）

**一句话**：一张好看的个人主页，放你的介绍、技能、作品链接、联系方式，生成专属小程序码方便分享。

- **类目**：工具类 - 办公（个人可做 ✓）
- **核心功能**（3-4 个）：
  1. 个人主页：头像、一句话介绍、技能标签、项目卡片（带外链）、联系方式
  2. 一键复制联系方式 / 跳转微信
  3. 生成小程序码 / 保存主页截图
  4. （可选）简单的访客统计
- **页面数**：1-2 页（主页 + 编辑页），交互低
- **vibecoding 友好**：★★★★
  - 几乎就是"静态页面 + 数据绑定"，AI 写静态布局最稳
  - 平台 API 极少：保存图片、复制到剪贴板
  - 不需要后端（数据写死或用本地存储）
- **展示亮点**：
  - **这个作品本身就是"展示你"的载体**——做成后它是你所有作品的入口
  - 设计感是核心卖点（好看的排版、动效、配色），AI 生成 WXSS 很稳
  - 小程序码发名片场景天然，朋友圈/微信群都能用
- **参考**：
  - Web：Linktree（linktree.com）、各种 personal portfolio
  - 小程序：搜"数字名片""个人主页"有大量同类
- **周期**：2-4 天
- **缺点**：功能简单，作为"作品"的工程含量偏低，靠设计感撑。如果你想简历加分明显，选 #2 更合适。

## 4. 报价/比价小工具

**一句话**：针对一个你熟悉的特定品类（咖啡豆、胶卷、机械键盘、镜头……），收录你关注的型号，显示当前行情/历史价格，帮做购买决策。

- **类目**：工具类 - 报价/比价（个人可做 ✓）
- **核心功能**（4 个）：
  1. 品类浏览（按系列/品牌分组）
  2. 型号详情：当前价、历史价格曲线、涨跌提醒
  3. 关注列表：自选型号的价格变动汇总
  4. 价格录入（用户手动，或接公开数据源）
- **页面数**：4 页（首页/详情/关注/录入），交互中等
- **vibecoding 友好**：★★★★
  - 数据驱动 + 简单图表（折线图），AI 写起来稳
  - 价格曲线用现成的小程序图表库（如 wx-charts、ec-canvas）
  - 如果接外部数据源，需要 `wx.request` + 定时更新，复杂度上升
- **展示亮点**：
  - 选一个**有故事性的小众品类**（比如"胶卷价格追踪""中画幅镜头行情"）会让作品显得"懂行"，比泛泛的比价工具有记忆点
  - 价格曲线图本身视觉好看
- **参考**：
  - Web：CamelCamelCamel（亚马逊价格历史）、各种比价站
  - 小程序：搜"比价"有同类
- **周期**：5-8 天
- **风险**：数据源是关键。手动录入起步最稳；接 API 会增加复杂度和不确定性。

## 5. 生活习惯打卡器（习惯环）

**一句话**：把"每天喝水/读书/锻炼"这类习惯做成可视化的"习惯环"（参考 Apple 健身圈的视觉），连续打卡让环变满。

- **类目**：工具类 - 健康管理（个人可做 ✓）
- **核心功能**（4 个）：
  1. 添加习惯（名称、目标频次、颜色、图标）
  2. 今日打卡页：每个习惯一个进度环，点击 +1
  3. 历史日历视图：哪天打了卡（热力图）
  4. 连续打卡天数 + 简单成就
- **页面数**：3-4 页（今日/历史/添加/设置），交互中等
- **vibecoding 友好**：★★★★
  - 数据驱动（`habits[]` + `records{date: habitId}`），核心是日期处理
  - 习惯环用 canvas 或 SVG-like（小程序的 view + WXSS 也能做圆环）
  - 本地存储就够，不需要后端
- **展示亮点**：
  - 视觉是核心（圆环动画、热力图），做得精致很像 Apple 健康
  - 连续打卡的成就感是留存点
- **参考**：
  - App：Streaks、Habitica、Apple 健身圈
  - 小程序：搜"习惯打卡"有大量同类（说明需求大，但也说明同质化）
- **周期**：5-8 天
- **缺点**：同质化严重，要脱颖而出全靠视觉打磨，作为"作品"识别度不如 #2。

## 关于"擦边 AI 类目"的提醒

你可能会想：能不能做一些"看起来像 AI 但不算深度合成"的方向来绕开类目限制？

**个人主体明确不能做"深度合成"类目**（这是 2023 年起对生成式 AI 的监管要求）。但有些方向**不属于深度合成**，可以放心做：

- ✅ **纯规则计算**：用 IF-THEN 规则、模板拼装（如"输入生日生成星座运势文案"用固定模板，不是 AI 生成）—— 但要注意不能伪装成 AI 算命骗人
- ✅ **信息聚合/查询**：调用公开数据 API 展示（天气、汇率、星座、节日）—— 这些是"查询"不是"生成"
- ✅ **本地小工具**：纯前端计算（单位换算、色卡、字体预览、css 速查）—— 完全不涉及 AI
- ❌ **调用大模型 API 生成文字/图片**：即使你只是套壳，性质上仍属于深度合成服务，个人主体不能上线

**建议**：第一版老老实实做"非 AI"方向（上面 5 个都是），把作品做出来。等以后有企业主体了再考虑 AI 类。
